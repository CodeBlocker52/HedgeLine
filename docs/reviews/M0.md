## Decisions made + why

1. **solc 0.8.30 for our code, auto-detect for the rest.** `reactive-lib-omni` needs `^0.8.29`; v4-core `PoolManager.sol` and 8 v4-periphery files are pinned `=0.8.26`. No single compiler satisfies both, so `auto_detect_solc = true` and `compilation_restrictions` pin `contracts/src/**` and `contracts/script/**` to `=0.8.30` (reproducible bytecode for Sourcify/BaseScan). Our pragma stays `^0.8.29` per Plan §4. Picked 0.8.30 over newer releases (up to 0.8.38 exists) as the oldest, longest-used release that satisfies `^0.8.29` other than 0.8.29 itself.
2. **`evm_version = "cancun"` in every profile.** v4-core needs transient storage; Lasna/Base/Unichain all executed Cancun opcodes in `eth_call`. Important: **Foundry 1.9 defaults to `osaka`**, so this must stay explicit. The `lasna` profile is identical today and is the escape hatch (`shanghai`) if M1 shows a mismatch.
3. **PoolManager in tests via artifact.** `contracts/test/utils/V4Artifacts.sol` (`=0.8.26`) imports PoolManager so its artifact exists; 0.8.30 tests deploy it with `deployCode("PoolManager.sol:PoolManager", ...)`. Proven by `test_poolManagerDeploysFromArtifact`. Note: locally compiled PoolManager is 19,725 B (our optimizer settings), not bit-identical to the deployed one (Uniswap builds with via_ir); fine for loopsim, use fork tests for real-bytecode checks.
4. **v4-core pinned to `59d3ecf5` (v4.0.0 + 12 commits), not the `v4.0.0` tag** forge picked — that's the exact commit v4-periphery's own submodule uses, so there is one consistent v4-core. The 12 commits are infra/test/npm only. v4-periphery is untagged; pinned at `c6e4754d` (`foundry.lock`).
5. **Scripts run on Node's native TypeScript** (`node --env-file=../.env x.ts`), so no `tsx`/`dotenv` dependency was added. Deps: `viem 2.57.13` (pinned, >2 weeks old), dev: `typescript 5.9.2`, `@types/node 22.18.6`.
6. `check-balances.ts` uses `DEPLOYER_ADDRESS` if set, otherwise derives the address from `PRIVATE_KEY`; never prints the key.
7. `deployments.json` has `contracts` and `txs` per chain; external infra (system contract, proxies, v4 addresses) lives in `scripts/lib/chains.ts` with a pointer to FACTS.md, so the registry only holds what *we* deploy.
8. Demos are cloned into gitignored `docs/research/demos{,-omni}/` (separate UNLICENSED repos) with re-fetch commands in demos.md.
9. CI excludes `contracts/test/fork/*` (needs RPC secrets).

## README ↔ Plan conflicts (not resolved — for the reviewer)

1. **S1 subscriptions.** Plan §3.7 subscribes to `PositionUpdated` **and** `PoolPriceUpdated`; README's subscription table lists only `PositionUpdated`. Plan §3.7 `react()` flow also never says what `PoolPriceUpdated` does. Every Unichain swap would cost a reactive tx.
2. **Hedger clamp.** README security model: "clamps every requested size to `h_max × reported delta`" and invariant `|short| ≤ h_max · Σ delta`. Plan §3.6: `|target| ≤ maxShortWad` and `|target − current| ≤ maxStepWad`. The hedger never sees Σ delta, so README's version isn't enforceable on Base as specified.

## Things in Plan.md I think are wrong or risky

1. **lREACT budget is the binding constraint.** Lasna gas price is 100 gwei and the system adds `_extraGas` = 100,000 to every reactive tx (`fee = 100 gwei × 1.0 × (gasUsed + 100k)`). With an *assumed* 200k gas per `react()`, that's 0.03 lREACT per reactive tx ⇒ ~166 txs from the current 5 lREACT. Each hedge loop fans out to several reactive txs (S2 swap + S3 `PositionChanged` + S3 `CollateralChanged`, plus S1 `PoolPriceUpdated` on every Unichain swap), and M4 needs ≥ 20 samples × 3 triggers plus scenarios and debugging. **Recommend topping up to ≥ 50 lREACT** (faucet: 1 ETH → 100 lREACT; needs ~0.5 Base Sepolia or Sepolia ETH we don't currently have). Base/Unichain gas is negligible (Base 0.006 gwei).
2. **Latency resolution on Base.** Confirmed with `cast`: Base Sepolia `block.timestamp` is whole seconds — 5 consecutive blocks share one timestamp. `HedgeApplied.timestamp` alone gives ±1 s on a loop that may be ~2–4 s. Suggest `latency.ts` also derive sub-second time from block position: `ts + 0.2 s × (block − first block with that ts)`, plus receipt wall-clock from `watch.ts` (already in the plan). Lasna and Unichain are 1 s blocks anyway.
3. **Token ordering (§3.2): use CREATE2 instead of "redeploy until sorted".** The deterministic deployer `0x4e59b44847b379578588920ca78fbf26c0b4956c` has code on Base Sepolia and Unichain Sepolia (`cast code`). Same salt + same init code ⇒ identical token addresses on both chains ⇒ identical token0/token1 ordering by construction. (Plain CREATE won't work: deployer nonce is 1 on Base, 0 on Unichain.)
4. **S3 cost/benefit.** The perp mirror could be fed from the hedger's own `HedgeApplied` / `MarginProtected` (one event per loop) instead of two MiniPerp events, halving S3 reactive txs. Keep S3 as specified unless budget bites; flagging.
5. **`BLOBBASEFEE` crashes Lasna `eth_call`.** Harmless unless code reads `block.blobbasefee`; recorded so nobody does.
6. **Callback gas sizing.** Base proxy withholds 80k + up to 50k before forwarding; with `callbackGasLimit = 1_000_000` the hedger gets roughly 870k. `applyHedge` → MiniPerp `setPosition` + `getSlot0` should fit; M2 gas test should assert < 60% of the forwarded amount, not of the limit.
