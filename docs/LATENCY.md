# Latency

All numbers on this page are generated by scripts from raw results; nothing is typed by hand.
Regenerate: `cd scripts && npm run m1-report` (reads `scripts/results/m1/E*.json`, writes `scripts/results/m1/report.md`).

## How to read the columns

- **whole-second**: difference of chain `block.timestamp`s. Exact to ±1 s.
- **estimated sub-second**: `timestamp + blockTime × position-in-second` (`scripts/lib/blocktime.ts`; Base Sepolia 200 ms blocks). An estimate.
- **wall-clock**: `Date.now()` when `scripts/lib/loop.ts` first saw each receipt/log, polling every 400 ms. Includes RPC visibility lag.
- **Total loop** = origin block → destination block. For E1/E3 both are Base Sepolia blocks (one clock). For E2 the origin is Unichain Sepolia.
- **Per-hop split is not reliable (M1 finding):** Lasna block timestamps run behind Base/Unichain (a Lasna tx is stamped −1…+1 s relative to its origin block, and always 2 s before the Base callback block), and Lasna `eth_getLogs` visibility lags Base, so "Lasna seen → dest seen" is often negative. Treat Lasna-side columns as diagnostics only.
